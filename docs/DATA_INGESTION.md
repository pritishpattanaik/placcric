# Match ingestion: import first

## Operating decision

PostgreSQL is the dashboard's source of truth. Obtain a finalized record once after a match (normally the CricHeroes scorecard PDF) and import corrections explicitly. Dashboard page loads never contact CricHeroes, and there is no crawler or polling. This avoids depending on website markup and repeated requests.

## Acquisition choices

| Route | Suitability | What must be confirmed |
| --- | --- | --- |
| Scorer/organiser sends structured JSON or agreed CSV | Preferred near-term route; no crawling | Format, accurate IDs and authority to share |
| Export offered to an organiser or Pro subscriber by their scoring system | Preferred if actually available | Supported format, access and redistribution terms |
| Authorised CricHeroes API/partner feed | Best future automation route if provided | Endpoint contract, coverage, credentials, limits and permissions |
| Final scorecard PDF/image supplied by scorer | Useful manual fallback | Human comparison against original before acceptance |
| PlacCric-native score entry | Independent alternative | Extra scorer workload, reconciliation and approval process |
| General cricket data API | Unconfirmed for this tournament | Exact tournament/match coverage before paying |
| Frequent website crawling | Excluded | Not required for this project |

## CricHeroes Pro: what is confirmed

As of 8 October 2026:

- **Confirmed (from a file the owner downloaded):** each match scorecard page offers **Download Scorecard**, which produces `Scorecard_<matchid>.pdf`. It is generated by a browser from the scorecard page (Chromium/Skia) and has a real text layer. It contains the tournament name and stage, teams, ground, date and time (UTC), toss, result, playing squads with captain/wicketkeeper marks, full batting (dismissal, R, B, minutes, 4s, 6s), extras breakdown, full bowling (O, maidens, R, W, dots, 4s, 6s, wides, no-balls), fall of wickets, did-not-bat lists and the scorer's and captains' names.
- **Not in the PDF:** CricHeroes player IDs, the match ID (only in the file name and link), ball-by-ball data, points table.
- **Not confirmed:** any API, bulk or tournament-level export, or partner feed. Search summaries of CricHeroes' PRO description list analytics, streaming, highlights, themes and ad-free use, not exports. CricHeroes pages could not be fetched from the development environment, so `robots.txt` and the terms of use have **not** been checked; automated fetching is therefore not built.

Source quirks seen in a real PDF: the same person spelled differently in different tables ("Md. Anowar Zahid" / "Md Anowar Zahid", "AU Mahi" / "Au Mahi"), and a batter not listed in the playing squad. PlacCric warns about squad mismatches and never merges names automatically.

## Today's workflow (implemented)

1. After a match is **completed**, download its scorecard PDF (or receive scorecard JSON from a scorer).
2. Upload it on **Data & imports**, choosing the tournament. The match ID is taken from the file name; a scorecard link can be added.
3. Review: totals and reconciliation checks (errors block approval), warnings, changes compared with the published match, and player identities.
4. Approve (publishes atomically as a new revision) or reject (nothing changes).
5. Re-uploading identical scores is a no-op; corrections show a field diff and create a revision; any revision can be restored.

Raw files are stored privately under their SHA-256 name with owner-only permissions, outside served directories and git. Keep the original downloads private too: they contain third-party names.

### Identity rules

- A name is identified per team. Once an admin confirms "this name, for this team, is this player", later imports recognise it.
- Suggestions (similar names in the same team, or the same name at another club) are shown but always need an explicit choice.
- A new player gets an internal ID unless the admin types the player's CricHeroes ID (from their profile link).
- JSON bundles carry CricHeroes IDs and need no identity step.

### Supported results

Completed two-innings matches with a winner. Ties, no-results, abandoned matches and super overs are rejected with a clear message until the competition's rules are defined. Rain-rule results (DLS/VJD) are imported with a warning.

## Proposed CSV support (Milestone 3)

Define and document a versioned contract before implementation: `matches.csv`, `innings.csv`, `batting.csv` and `bowling.csv`, joined by provider/match/innings/player IDs. UTF-8, integer legal balls or cricket-notation overs, schema version, source and timestamps. Provide empty templates and fixtures. Reject duplicate keys and inconsistent totals with row-specific errors.

CSV fields must not be silently mapped to scorecard facts. Names alone are insufficient to merge players. OCR, if ever added, must retain confidence and source page/cell, never invent missing names or figures, and require human review before data counts as verified.

## Provider integration later

If CricHeroes confirms an approved webhook, accept signed events idempotently; otherwise use an agreed, bounded, manually triggered synchronisation. Neither is confirmed. Keep the adapter separate from analytics so file imports keep working offline.
